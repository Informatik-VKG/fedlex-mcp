# ADR 0002 — Authentication & gateway posture

**Status:** Accepted · **Date:** 2026-06-03

Addresses audit findings SEC-009 (session crypto-binding), SEC-014 (tool
allow-listing) and SEC-015 (pre-flight tool-poisoning detection).

## Context

`fedlex-mcp` exposes public open data with **no authentication** (`auth_model:
none`) and no user identity. Several audit checks are written for authenticated
and/or enterprise-gateway-fronted servers. This ADR records how each is handled
for the current no-auth deployment and the explicit trigger to revisit.

## Decisions

### SEC-009 — Session crypto-binding → N/A (no auth), revisit on auth
There is no user identity to bind a session to. MCP Streamable-HTTP session IDs
are generated by the `mcp` SDK's session manager. Binding a session to a
validated OAuth `sub` claim is **only meaningful once authentication exists**.

**Trigger:** if/when any auth model (API-Key, OAuth-Proxy, OIDC) is added,
implement `secrets.token_urlsafe` session IDs bound to the validated user, TTL,
and server-side invalidation — and re-audit before merge.

### SEC-014 — Tool allow-listing → implemented (server-side) + gateway guidance
A server-side, default-deny allow-list is implemented: setting
`FEDLEX_ENABLED_TOOLS` (comma-separated) registers **only** those tools; the
rest disappear from `tools/list` and are not callable. This is
defense-in-depth that complements — not replaces — a gateway allow-list.

```bash
FEDLEX_ENABLED_TOOLS="fedlex_search_laws,fedlex_get_law_by_sr" python -m fedlex_mcp.server
```

For enterprise / multi-team deployments, the upstream MCP gateway should apply
per-team/role allow-lists and audit denied calls; that layer is out of this
repo's scope.

### SEC-015 — Pre-flight tool-poisoning detection → gateway concern + compensating control
Pre-flight scanning of tool definitions for prompt-injection / homoglyph /
invisible-character payloads is a **gateway-layer** responsibility and is not
implemented in the server. Compensating controls already present in this repo:

- **SEC-022 tool-hash pinning** (`tool-definitions.lock.json`) makes any change
  to *this server's own* tool definitions detectable (rug-pull guard).
- All tool descriptions are static, authored in-repo, and reviewed via PR.
- The server is read-only with a single fixed egress host (see ADR 0001).

**Trigger:** if this server is placed behind a shared MCP gateway, enable the
gateway's tool-poisoning detection and SIEM alerting.

## Consequences

- No-auth scope keeps SEC-009 explicitly out of scope with a clear re-audit trigger.
- SEC-014 has a concrete, testable server-side control plus documented gateway guidance.
- SEC-015 is delegated to the gateway with SEC-022 as the in-repo compensating control.
